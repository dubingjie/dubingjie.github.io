迭代器 · 生成器

一、可迭代对象 vs 迭代器对象

1. 通俗类比

  • 可迭代对象（Iterable） = 一本可以翻的书
  • 迭代器（Iterator） = 一个会自己翻页的书签

书本身不会自己翻页，你得找个书签帮你翻。书签记得”我翻到第几页了”。

10. 总结

可迭代对象 = 能被遍历的东西（书）
迭代器 = 能被遍历 + 会自己往下走 + 一次性（书签）
可迭代是”资格”，迭代器是”能力”。

二、生成器（Generator）

1. 通俗类比

  • 普通函数 = 一次性把菜全做完端上来（列表）
  • 生成器 = 现做现上，你吃一口我做一道

2. 生成器是什么

生成器是一种特殊的迭代器。

特点：

  1. 用 yield 代替 return
  2. 不会一次性算完，而是”要一个给一个”（惰性求值）

一句话：生成器 = 会”暂停”的函数 + 自动成为迭代器。

12. 总结

有 yield 就是生成器函数，圆括号推导式就是生成器表达式。
yield = 暂停 + 返回值 + 记住现场。
生成器 = 惰性求值 = 要一个算一个 = 省内存。

三、生成器的两种调用方式

1. 手动调用

基础：用 next()

半自动：用 for

真正的手动：用 send() 双向通信

典型场景：实时平均值

2. 用装饰器调用

问题：用 send() 前必须先 next() 启动，容易忘。

解决：自动启动装饰器

官方例子：@contextmanager

3. 对比表

对比项 手动调用 装饰器调用
谁控制流程 你亲自 next/send 装饰器帮你启动/包装
启动步骤 必须手动 next(g) 自动完成
代码复杂度 灵活但要小心 简洁，逻辑清晰
典型用途 协程、双向通信 上下文管理器、自动启动

4. 总结

手动调用：你自己用 next() 和 send() 驱动生成器。
装饰器调用：装饰器帮你自动启动或包装生成器。
本质：都是”驱动生成器”，一个亲手，一个代劳。
